Authority：使用者以 Director 身分於 2026-09-13 在對話中裁示，2026-09-14 補足兩項通用性
裁決，供 OpenSpec change `author-farm-pest-spread` 使用。授權形式沿用
`../../farm-twin-topology/director-decisions/2026-09-05-farm-crop-group-assignment.md`
（「the user, acting in the Director role … ruled in conversation」）。本檔是擴散規則的
來源紀錄：凡是引用擴散結果的記錄，都以本檔的版本庫路徑與 SHA-256 引用它。

以下每一個值都是**宣告的展示與模擬選擇**，並附上依據。沒有任何一項是量測、流行病學
模型、病蟲害發育模型，或對六堆雅歌園有機教育農場的觀察。「模擬」標示只揭露狀態，不會
讓沒有依據的主張變成有依據，所以依據在此明寫，而不是靠標示暗示。

本檔以繁體中文書寫，依使用者 2026-09-13 的指示；技術識別字（ID、欄位名、路徑）保留原文。

## 為什麼需要一條規則

2026-09-05 的作物分組裁示轉述了老闆 2026-09-04 的規則，並在其範圍段明文寫著它
「does not authorize a spread rule」。本檔就是那份缺少的裁示。

老闆的規則，由使用者於 2026-09-04 轉述：

> Will說用作物分吧 所以你設定會先跑到最近的同樣作物的田擴散 先跑同農場 再跑隔壁隨便哪個
> 我們現在還不知道 沿山185 有哪些農場有數據

這個展示的觀眾是計畫審查委員與老闆，而它必須讓觀眾看懂一件事：**病蟲害是照作物擴散，
不是照距離。** 計畫自己的簡報把痛點寫成病蟲害蔓延快而生物防治成本高，並把 3D 分身的
展示語境定為病蟲害熱區與傳播趨勢。一張靜態圖可以畫出熱區，但只有會動的序列，才能讓人
看見「最近的鄰田沒事，較遠的同作物田先出事」。

## 裁示的值

```
傳播範圍：   只在宣告了同一個作物分組 token 的 Face 之間

距離算法：   兩個 Face 多邊形之間的最短距離（邊到邊），在已接受的 local_m 框架量測，
             量化到 0.001 m 之後才進行比較

選擇方式：   在所有「尚未受影響、且與感染區帶同一 token」的 Face 之中，取離
             「整個已受影響集合」最近的那一塊。某塊候選 Face 與集合的距離，定義為
             它與集合中每一塊的距離取最小值；取到該最小值的那一塊已受影響 Face，
             即為本次傳播所記錄的來源

平手時：     stable ID 在字碼順序中較小者優先

觸發：       當一塊 Face 進入第 4 級「擴散中」時（進入當下的一次性事件，不是
             「處於第 4 級以上」的持續狀態），依上述選擇方式選出的 Face 從第 2 級
             「觀察中」開始

同格多來源： 同一格內每有一塊 Face 進入第 4 級，就進行一次傳播。多次傳播依觸發來源的
             stable ID 字碼順序**依序**解算：每選出一塊就併入已受影響集合，下一次再
             重新計算，因此同一格的兩次傳播不會選到同一塊

惡化：       新受影響的 Face 每格沿宣告的階梯升一級，至第 5 級封頂；只升不降，
             不做任何處置

停止：       該組已經沒有尚未受影響的 Face，或十分鐘序列結束，以先發生者為準

起點：       由情境輸入指定，規則本身不寫任何 Face 的名字

邊界：       僅限本農場之內（見下方〈跨農場〉）
```

**規則裡不出現任何一塊田的名字。** 起點、受影響的集合與順序，都是由宣告的 token 和已
接受的幾何，對「當下存在的 Face」計算出來的；因此新增一塊田或改變分組，結果會變，而
規則不用改。

### 「只傳同作物」的依據

老闆的規則。它的結果正是這個展示的重點：以邊到邊量測，從 `field-alpha` 到
`greenhouse-bay-a` 是 7.01 公尺、到 `greenhouse-bay-b` 是 7.65 公尺，而同組中最近的
`field-beta` 是 17.70 公尺。照距離的規則會先到溫室；本規則會跳過兩個溫室，先到
`field-beta`，再到 `field-delta`（距 `field-beta` 3.37 公尺）。兩個溫室與 `field-gamma`
在整段展示中保持健康，這個對比就是論點本身。

### 距離算法的依據

「最近」有三種誠實的讀法，六塊受管 Face 兩兩之間都量測過：頂點最近、邊到邊、形心到
形心。對目前這六塊田而言，從 `field-alpha` 出發，三種讀法給出相同的順序，所以這個選擇
並沒有替今天的結果動手腳。裁示採「邊到邊」，理由是它最接近農夫說的「隔壁那塊田」：兩塊
田相鄰時為 0，而且一塊田被重新描繪、頂點變多時，結果也不會跟著跑掉 —— 後者不是假設，
`reauthor-farm-geometry-from-director-visual-identification` 正在替五塊 Face 換座標。

比較前先量化到 0.001 m，是為了讓浮點殘差不能決定結果。沒有這一步，平手規則永遠不會
觸發，而兩次烘焙的差異會躲在小數尾巴裡 —— 那正是逐位元組相同閘門最難診斷的一類失敗。

### 選擇方式的依據（離整片感染區最近，而不是離剛觸發的那一塊最近）

2026-09-14 裁決。兩種讀法在本次展示結果完全相同（a 組只有三塊，第三塊是唯一剩下的
候選），差別只在同一組有四塊以上田時才顯現 —— 也就是這座農場的田陸續進來之後。

採「離整片感染區最近」的理由是另一種讀法會產生站不住的結果。假設同組有四塊田，甲先
發病、傳給最近的乙；接著換乙往外傳，而乙最近的未感染是三十公尺外的丙，另有一塊丁就在
甲隔壁五公尺。若只看「剛觸發的那一塊」，就會傳給三十公尺外的丙，而甲隔壁五公尺的丁
沒事。審查委員會直接問「為什麼隔壁五公尺的沒事，較遠的先中」，而「因為剛惡化的是乙不是
甲」這個理由沒辦法讓人接受，並且正好削弱本展示唯一要證明的事。

本讀法同時讓每一次傳播仍有明確的一對一來源（集合中距離最小的那一塊），所以 provenance
不會變糊；也讓閘門的「跳過更近的同組 Face 即阻擋」檢查範圍從單一來源的鄰居擴大為整片
感染區的鄰居，手寫死的鏈條更難通過。

### 觸發等級的依據

在已接受的階梯中，第 4 級的標示本來就是「擴散中」。在名稱就叫「擴散」的等級才開始擴散，
可以讓詞彙與行為一致；同時讓第 3 級「初期」——也就是宣告的生物防治窗口——保持為「當時
處理還來得及」的那一步。觸發定為「進入」該級的一次性事件，而不是「處於該級以上」的持續
狀態，否則一塊停在第 5 級的田會每一格都再傳一塊，鏈條長度將由序列長度而非幾何決定。

### 同格多來源的依據

2026-09-14 裁決：多點同時進入「擴散中」時，該格就發生多次傳播，而不是只准一次 ——
否則「多處同時爆發」在展示中看不出來。依序解算而非同時解算，是「離整片感染區最近」的
必然結果：選擇只取決於感染區，若兩個來源各自獨立計算會得到同一塊目標。依 stable ID
字碼順序依序解算，使結果與輸入順序、迭代順序無關。

## 本次展示的情境值

以下是輸入，不是規則。修改它們不需要取代本裁示。

```
起點：      field-alpha，於第 1 格被觀察為第 2 級「觀察中」
來源節奏：  第 0～5 格 → 第 1、2、3、4、5、5 級
```

在已接受的固定時鐘（6 格 × 100 秒）下，這十分鐘會是：

| 格／秒 | 拍 | field-alpha | field-beta | field-delta | gamma、溫室 A/B |
| --- | --- | --- | --- | --- | --- |
| 0 ／ 0 | 巡檢 | 健康 | 健康 | 健康 | 健康 |
| 1 ／ 100 | 警報 | 觀察中 | 健康 | 健康 | 健康 |
| 2 ／ 200 | 限制與回應 | **初期（窗口）** | 健康 | 健康 | 健康 |
| 3 ／ 300 | 教育路線 | 擴散中 | 觀察中 | 健康 | 健康 |
| 4 ／ 400 | 教育路線 | 嚴重 | 初期 | 健康 | 健康 |
| 5 ／ 500 | 教育路線 | 嚴重 | 擴散中 | 觀察中 | 健康 |

第 3 格：`field-alpha` 進入「擴散中」，感染區為 {alpha}，同組未受影響者中離感染區最近
的是 `field-beta`，來源記為 `field-alpha`。第 5 格：`field-beta` 進入「擴散中」，感染區
為 {alpha, beta}，未受影響者只剩 `field-delta`，其與感染區的最小距離取自 `field-beta`
（3.37 公尺，遠小於它與 `field-alpha` 的距離），故來源記為 `field-beta`。

有兩個後果在此記錄，不隱藏。第一，來源節奏與目前已接受的「什麼都不做」基線所烘焙的
`1,1,2,3,4,5` 不同；往前移一格，才會讓警報落在顯示「觀察中」而非「健康」的田上，也才
能讓鏈條在十分鐘內傳到第三塊田。這是對已接受能力的更動，需要它自己的 change 與審查，
並依〈Gate provenance〉重新烘焙後開出**新的**日期收據，既有收據不得改寫。第二，這段
展示結束時 `field-delta` 才剛開始；序列比鏈條先結束，本裁示不編造任何東西去把它補完。

## 這條規則不是什麼

- **不是流行病學。** 沒有速率、潛伏期、感染機率，沒有氣象、風、溼度或溫度輸入，也沒有
  蟲種。等級是宣告的、不透明的一步；一次傳播是 token 與幾何的宣告結果。
- **不是診斷，也不是監測輸出。** 這裡沒有任何東西在觀察這座農場。偵測那條線——農夫用
  手機拍葉片、另一個團隊的模型判讀——屬於後續的整合，本檔不授權它。
- **不是建議。** 這段展示是「什麼都不做」的基線。它呈現的是錯過窗口會怎樣，而不是建議
  任何處置、時程或回應；任何畫面都不得讀起來像建議。
- **不產生新的 runtime 權威。** 擴散結果只有在 canonical frame 把它放到某個穩定 twin ID
  上時才成立。烘焙端依固定情境輸入計算本規則，做法與已接受的群聚距離規則相同；播放端
  不計算任何距離，也不推論任何狀態。

## 跨農場

本裁示不涵蓋，理由是老闆自己的話：「我們現在還不知道 沿山185 有哪些農場有數據」。他規則
的後半段——「先跑同農場，再跑隔壁隨便哪個」——是**延後**，不是否決：這個版本庫裡沒有任何
鄰近農場的 Face，沒有鄰田經過確認的作物，也沒有來自鄰田的掃描資料。上面的規則是寫在
「所有同組的 Face」之上，所以將來要延伸到鄰近農場，是資料的問題，不是規則的問題。

## 授權限制

- `authority_scope`：`simulation-input`。
- `surveyed_or_measured_claim`：false。
- 本規則不得被呈現為診斷、監測輸出、感測讀值、作業指示或處置建議。
- 本規則不授予任何 runtime 權威。一次擴散只有在 canonical frame 把它放到穩定 twin ID
  上時才成立。
- 不授權任何 dressing、上色、顏色或散佈的變更。**但這個展示最重要的論點需要它**：一塊
  Face 目前畫出來是一片薄板，內部顏色與地形相同，所以階段只能被點開檢視，無法一眼看出。
  讓擴散看得見屬於後續的呈現 change，其前置問題記錄在 issue #54。
- 不授權 bake、accepted export 升格、viewer 交付、AI 偵測接入、農藝主張，也不授權更動任何
  Face 的幾何、穩定 ID 或作物分組 token。

## 可修訂性

與作物分組裁示、健康階梯裁示適用同一道證據閘門：由一份較晚的、具名授權與日期的裁示取代
它，並且所有引用本檔的記錄都改引用取代它的那一份。修改距離算法、選擇方式、觸發等級或
停止條件，只是對本檔與其被引用的雜湊做 token 層級的編輯；不會移動任何幾何，也不會動到
任何穩定 ID。

## 範圍

本裁示僅規範十分鐘展示中，農場田區 Face 之間的模擬擴散。它不授權 bake、dressing 變更、
農藝主張、作業建議、偵測資料接入、鄰近農場的 Face，也不授權更動已接受的作物分組指派或
健康階梯。
